## Quality Bar

**Target quality:** A runtime rebind that a game drives from its own menu, and a text form of the binding list that the game stores in its own file. binding-remap closes the input epic. It writes into the tagged bindings that control-schemes shipped. It reads the raw state that input-state shipped, and it uses the pad values that gamepad-axes baked its deadzone into. This is an API-and-interaction feature, so four things carry it. A wrong state machine leaves a half-open listen or lands a dead binding. A hidden allocation in the listen fails the HelloPanel gate and the seventeenth gate in each frame. A silent data loss in the round trip drops a binding that the game stored. A break of the shipped 18-bind surface stops every game that builds a map, spacegame map-controls first.

- **Correct state machine:** One listen, seven states (closed, settling, open, rejected-and-open, cancelled, committed, restored), and one exit per event. A test pins every rule. The cancel key cancels, and the listen consumes it. `CancelRebind` leaves no change, and a mismatched capture stays in the listen and reports the reason. No dead binding can land in the map, and the listen ends with no commit on `Activate` and `Deactivate`.
- **No hidden allocation:** `BeginRebind`, `CancelRebind`, the capture scan, the fit test, the commit, the conflict check, the two slots, and `ResetBindings` allocate 0 bytes in the default Debug build. `ActionMapAllocationTests` gains a body that drives a live rebind and a restore, keeps the fixed-increment real-work assert, and a plant fails it (A1). `WriteBindings` and `ReadBindings` run at load time and may allocate.
- **No silent data loss on a round trip:** All nine `InputKind` shapes write and read back (Q10), with `code`, `code1`..`code3`, `mods`, and `scale` present when they are not at their default. A short span returns the needed count and writes nothing (A7). The read skips each bad line, counts it, and throws nothing (A8). `ReadBindings` merges per action and scheme and keeps what the text does not name (Q6).
- **No break of the shipped surface:** The 18 public `Bind*` signatures and the two `AddAction` overloads keep their text. So do the five queries, `PushGamepad`, `PressKey`, `PressMouseButton`, and `InvokeAction`. So do `Activate`, `IsActive`, `Deactivate`, and `GamepadSlot`. So do `AddScheme`, `SchemeName`, `ActiveScheme`, `LockedScheme`, `SetScheme`, and `OnSchemeChanged`. The eleven current bind signatures and the nine scheme overloads change no line.
- **A small named diff:** Framework-only and csproj-free (A2). No `BrutalUi.Core` file, no `BrutalUi.Glfw` file, and no project file changes. Two new partial files and three edited files in `src/BrutalUi.Framework/Actions/` hold the whole feature.
- **Accurate docs:** Section 9 gains item 15 with the listen rules and the conflict rule, and item 16 with the full line grammar and the nine `device` numbers. Section 14 gains one test bullet. `CHANGELOG.md` gains one line tagged `(input/binding-remap)`. Each public member has an XML doc comment in ASD-STE100 prose (CS1591 is an error).

## Executive Summary

This feature lets a game rebind an action at run time and keep the result as text. The map opens a listen and scans the raw input in each frame. It commits the first fitting input as the new binding of one action in one scheme. It reports a conflict with both action names, restores the build defaults, and writes or reads the whole binding list as UTF-8 lines. The game owns the file, and Framework does no file IO.

- `UiActionMap` gains the listen (`BeginRebind`, `CancelRebind`, `IsRebinding`, `RebindCancelKey`, `OnRebindResult`), the conflict slot (`OnRebindConflict`), the restore (`ResetBindings`), and the text pair (`WriteBindings`, `ReadBindings`). `UiScheme.Default` ships as `public const int Default = 0` (deferred review CR-8). No new top-level public type appears (A10).
- Two new partial files follow the shipped split. `UiActionMap.Remap.cs` holds the listen state, the capture scan, the fit test, the commit, the conflict report, `ResetBindings`, and the defaults snapshot. `UiActionMap.BindingsText.cs` holds `WriteBindings`, `ReadBindings`, the internal line codec, and the internal binding handle that review CR-5 asks for.
- The listen branch sits inside the existing `ReadFrame` pass (`UiActionMap.Read.cs:259`) right after its pair test. The frame read therefore stays the one place that reads input (A1). It reads `context.Input`, the raw view, and not `context.GameInput` (Q1). A suppressed frame writes no value and runs no command on all five invoke paths. It emits no release edge, and it keeps the device track and `OnSchemeChanged` running (Q9).
- A conflict commits the new binding first, names both actions through the slot, and keeps both by default (Q8). The commit writes the binding array directly, past the throwing `FindClash` bind-time check.
- The text form is one version line, then one `key=value` line per binding, with the `device` field carrying the numeric `InputKind` id (Q3, Q10, A7). `InputKind` gains explicit values so the nine numbers cannot move.
- HelloPanel rebinds one key live through a button and restores it through a second button, and shows the listen state in a seventh label (Q7, A6 of the epic).

The plan has 5 phases and 44 tasks, about 345 steps. Phase 1 (16 tasks, two groups, ADVANCED) delivers the listen, a key capture, the commit, the cancel, and the silence. It also delivers the HelloPanel rebind, the demo that Q7 names. Phase 2 (5 tasks) delivers the full seven-shape capture table and the mismatch reject. Phase 3 (7 tasks, ADVANCED) delivers the conflict report, `ResetBindings`, the defaults snapshot, and the Restore button. Phase 4 (9 tasks, two groups) delivers `WriteBindings`, then `ReadBindings` and the round trip. Phase 5 (7 tasks, two groups) grows the seventeenth gate and writes the docs.

**Target Users:**
- [ ] **The game developer** opens a listen from its own rebind menu. It reads the outcome and the conflict through two slots, and keeps the list in its own file through `WriteBindings` and `ReadBindings`.
- [ ] **The player who remaps a key** clicks a button, presses a key, sees the conflict, and restores the defaults.
- [ ] **The mod and save-file author** reads and writes a plain UTF-8 binding file with a version line and one binding per line.

**User Subsets Served:**
- [ ] **Simple** - a game calls `map.BeginRebind(UiActions.Confirm, UiScheme.Default)`, the player presses a key, and the action moves to it.
- [ ] **Complex** - a game rebinds one action per scheme, reads the two action names of a conflict, and asks the player. It restores the build defaults, writes the list at exit, and reads it back at load. The read merges per group and counts the skipped lines.

**UX Approach:**
- Runtime: `BeginRebind` opens the listen, and the map needs one call per rebind and nothing else. The frame read drives the whole state machine inside `UiContext.Update(float)`.
- Load time: `WriteBindings` and `ReadBindings` run outside the frame loop, and the game owns the file (Out of Scope).
- No rebind screen, no widget, no glyph, no key-name table, and no part-by-part composite rebind (Out of Scope).

### The Listen State Machine

| State | Fields | Entry | Exit |
|---|---|---|---|
| Closed | `_rebindOpen = false` | construction, `ResetFrame`, every commit, every cancel | `BeginRebind` |
| Settling | `_rebindOpen = true`, `_rebindSettle = 1` | `BeginRebind` | the next `ReadFrame`, which clears the counter and stays open |
| Open | `_rebindOpen = true`, `_rebindSettle = 0` | the settle frame | a candidate closes it or reports a reject |
| Rejected | open, unchanged | a candidate that does not fit the action type | the listen stays open and the map reports `RebindRejected` |
| Cancelled | closed | the cancel key, `CancelRebind`, `ResetBindings` | `BeginRebind` again |
| Committed | closed | one fitting candidate | `BeginRebind` again |
| Restored | closed, no snapshot until the first `Activate` | `ResetBindings` | the same listen path as Closed |

Rules that the table cannot carry:
- **Settle.** `BeginRebind` sets `_rebindSettle = 1`, and `RebindScan` returns from the scan in the frame that it lands. The scan then reads only press edges. This is what keeps the click or the key that opened the listen out of the new binding. A value that is held across the settle frame is still a candidate after it, so the scan needs no per-code down memory.
- **One candidate per frame.** The scan reads the seven capturable shapes in the `InputKind` order: Key, MouseButton, GamepadButton, GamepadStick, GamepadAxis, MouseDelta, Scroll. The first live shape is the candidate, and the fit test then accepts or rejects it. A frame with two live shapes commits the first one, even when the second would fit.
- **A digital capture needs a fresh edge.** Key uses `Keys.WasPressed`, MouseButton uses `Buttons.WasPressed`, and GamepadButton uses `pad.Pressed`. The scan ignores `IsDown` and `pad.Buttons`, so it never takes a binding from a press that already landed. The HelloPanel demo proves it: the click that opens the listen does not become the binding.
- **The cancel key beats the fit test.** The scan tests the cancel key first, so Escape cancels even when Escape is a mismatch for the target action.
- **A reject keeps the listen open**, so the player can try again. The map reports `RebindRejected` with the code of the rejected input, and it reports again in each frame that a rejected candidate stays live.
- **A commit consumes the press that landed it**, because `RebindScan` returns from `ReadFrame` and the value loop never reads the new binding in that frame. The player presses the new key a second time to drive the action.
- **`Activate` and `Deactivate` close the listen** with no commit and no slot call, because `ResetFrame` clears `_rebindOpen` and `_rebindSettle`.

### The Capture Table (A5)

`device` in a text line is the numeric `InputKind` id. The seven capturable shapes and the three that no rebind can make:

| Shape | `InputKind` (#) | Live when (raw view) | Accepts | `code`, `mods`, `scale` written |
|---|---|---|---|---|
| Key | `Key` (0) | `input.Keys.WasPressed(k)`, k 0..348 | Button | `code = k`, `mods = input.Keys.Modifiers & MatchMask`, `scale = 1f` |
| Mouse button | `MouseButton` (1) | `input.Buttons.WasPressed(b)`, b 0..7 | Button | `code = (int)b`, `mods` as above, `scale = 1f` |
| Gamepad button | `GamepadButton` (2) | one bit set in `pad.Pressed` | Button | `code = the bit`, `mods = None`, `scale = 1f` |
| Gamepad stick | `GamepadStick` (4) | `pad.LeftStick` or `pad.RightStick` is not (0, 0) | Vector2 | `code = (int)UiGamepadStick`, `mods = None`, `scale = 1f` |
| Gamepad axis | `GamepadAxis` (5) | `pad.Axis(a) != 0f`, a 0..5, scanned after the sticks | Axis | `code = a`, `mods = None`, `scale = 1f` |
| Pointer delta | `MouseDelta` (7) | `input.Pointer.Delta` length above the threshold | Vector2 | no code, `mods = None`, `scale = 1f` |
| Scroll | `Scroll` (8) | `input.Pointer.ScrollDelta.Y != 0f` | Axis | no code, `mods = None`, `scale = 1f` |

A rebind never captures a composite: `KeyVector` (3) and `KeyAxis` (6) need two or four keys, and a part-by-part composite rebind is Out of Scope. A rebind of the action can still remove a composite binding that the map holds, and the text format can read one back on a line.

The scan takes the stick before the axis, so a stick move gives a `GamepadStick` capture and not a `GamepadAxis` capture of axes 0..3. A stick at rest reads exactly (0, 0), because the poll baked the deadzone in (A5). The delta threshold is `RebindDeltaThreshold = 8f` device-independent pixels, a private constant. A raw pointer delta is unfiltered screen movement, so "not exactly 0" is too weak for it. The map stores no deadzone of its own.

### The Commit, the Group Rule, and the Conflict

`BeginRebind(action, scheme)` names the tag that the new binding gets, and the set of bindings that it replaces: exactly the bindings whose action index and `Scheme` id both equal the target (Q5, Q11). The target is the whole action inside one scheme, so a rebind of a `Move` action that holds a `KeyVector` and a stick in two schemes replaces only the bindings of the named scheme.

```
FindConflictAction(in Captured c, int scheme)        BEFORE the commit, so a compaction cannot move an index
  for i in 0.._bindingCount:
    if (_bindings[i].Kind == c.Kind && _bindings[i].Code == c.Code
        && _bindings[i].Modifiers == (c.Modifiers & MatchMask)
        && SchemeClashes(_bindings[i].Scheme, scheme)
        && _bindings[i].Action != _rebindAction)  { return _bindings[i].Action; }
  return -1;

Commit(in Captured c, int clashAction)
  RemoveBindings(_rebindAction, _rebindScheme);      // in-place compaction, no Array.Resize
  Append(new InputBinding { Kind = c.Kind, Code = c.Code, Code1 = -1, Code2 = -1, Code3 = -1,
                            Modifiers = c.Modifiers & MatchMask, Scheme = _rebindScheme,
                            Scale = 1f, Action = _rebindAction });
  _rebindOpen = false; _rebindSettle = 0; _rebindAction = -1;
  OnRebindResult?.Invoke(this, targetName, RebindBound, c.Code);
  if (clashAction >= 0) { OnRebindConflict?.Invoke(this, targetName, _actions[clashAction].Name); }
```

- The commit bypasses `FindClash` (`UiActionMap.Bindings.cs:1137`), which throws, so a conflicting rebind lands and both bindings stay (Q8, A4). `FindClash` keeps its exact text and its bind-time role.
- The clash scan reads the index of the other action before `RemoveBindings` moves anything. The shipped `FindClash` returns a binding index and throws the action of that binding away. This is review CR-5 of input-actions.
- The conflict scan reuses `SchemeClashes` (`UiActionMap.Schemes.cs:269`), so a clash against a `Scheme = 0` binding reports in either direction (A4). The set rule of CR-3 stays intact for the composites that a rebind cannot make.
- `Append` (`UiActionMap.Bindings.cs:1276`) doubles the array, so `RemoveBindings` runs first. The removed slot frees the room, so the grow does not happen in the frame path (A1). The count bounds every read, so the code needs no `Array.Clear`.
- The new binding lands at the end of the array, so a conflicting input resolves to the earlier binding on `PressKey` and both flags on the frame read. Notes and Risks name this order change.

### The Defaults Snapshot and the Restore (A6)

`Activate` calls `CaptureDefaults()` once, on the first activation only, guarded by `_defaultsCaptured`. The copy is `new InputBinding[_bindingCount]` plus the count, so the snapshot costs one array at activation time. `ResetBindings` writes the snapshot back into the existing array with an in-place copy, then restores the count. It never reassigns `_bindings`, so the restore allocates nothing.

- The snapshot comes before any rebind, and `ReadBindings` does not change it (A6). A game that binds after its first `Activate` loses those binds on a restore, and section 9 says so.
- A map that was never activated holds no snapshot, so `ResetBindings` gives `false` and changes nothing.
- `ResetBindings` closes the listen with no commit and no slot call. It leaves `ActionCount`, the action types, the commands, the scheme table, `GamepadSlot`, and the scheme lock alone. It restores bindings only (requirements line 15).

### The Text Format

One version line, then one line per binding, in the order of the binding array. The text is UTF-8, with `\n` line endings, `;` between fields, `=` between a field name and its value, and no space padding (Q3). A field appears only when its value differs from the `InputBinding` default of the capture table above.

```
version=1
action=NavigateUp;scheme=KeyboardMouse;device=0;code=265
action=Fire;scheme=-;device=0;code=32;mods=2
action=Zoom;scheme=Gamepad;device=5;code=4;scale=-1
action=Look;scheme=Gamepad;device=7
action=Move;scheme=KeyboardMouse;device=3;code=87;code1=65;code2=83;code3=68
```

| Field | Present | Value | Rule |
|---|---|---|---|
| `version` | the first non-empty line only | `1` | `BindingsVersion = 1`, a private const |
| `action` | always | the action name bytes | the map compares names by bytes, as `IndexOfAction` does |
| `scheme` | always | the bytes of `SchemeName(id)`, or `-` for id 0 | `SchemeName(0)` is empty, so the writer emits a token (A3) |
| `device` | always | the numeric `InputKind` id, 0 to 8 | the capture table pins the nine numbers with explicit values |
| `code` | when not `-1` | a number | a key code, a pointer button value, a gamepad bit, a stick or axis index |
| `code1`..`code3` | when not `-1` | a number | the `KeyVector` and `KeyAxis` composites |
| `mods` | when not 0 | a number | the `UiModifiers` mask, always inside `MatchMask` (1, 2, 4, 8) |
| `scale` | when not 1 | a number | the `InputBinding.Scale` value, invariant culture |

- Numbers only: a key code is a number, and a modifier set is a number. Framework ships no key-name table (Q2). Section 9 states the nine `device` numbers and the four `mods` bits, so a file has one written contract.
- `WriteBindings(Span<byte>)` returns the byte count. A span that is too short returns the needed count and writes nothing (A7). The measure pass and the write pass share one private line writer, so the two counts agree exactly.
- A short-span return has no precedent in `src/`. `TextField.GetText(Span<byte>)` returns the bytes written and never a needed count. The HelloPanel formatters throw `InvalidOperationException` when their scratch is too small. Decision 6 records the shape and its reason.
- `ReadBindings` merges per pair: for each action and scheme pair that the lines name, it replaces the bindings of that pair. A pair that no line names stays (Q6). The read skips and counts each bad line, and throws nothing (A8). A bad line holds an unknown action, an unknown field, a repeated field, or a missing `action`. It holds a bad number, a non-finite scale, an out-of-range code, or an unknown `device` number. It holds a scheme name that the map does not hold. No dead binding can land, because each value passes the same range checks that the binds run (CR-6 of input-actions).
- An unknown version applies nothing and reports the version as the failure. It gives `Applied` 0 and `Version` the number read. A text with no version line, an unreadable version, or the version line on a later line gives `Version` 0 and applies nothing (A8).
- Both members run at load time and may allocate. The reader copies the good lines into a private growable array before it touches the map, so the merge needs two passes and one compaction. Neither member touches the frame path.

## Key Technical Decisions

### Confirmed Assumptions

- Q1 Capture source: the listen scans the raw `context.Input`, and not the gated `context.GameInput`. A rebind then works while a widget holds focus or a pickable root covers the window.
- Q2 Code form in a text line: numbers only (a numeric code and a numeric modifier mask). Framework ships no key-name table.
- Q3 Grammar: named `key=value` fields, one binding per line, plus a version header line.
- Q4 Mismatched capture: reject the input, stay in the listen state, and report the reason through a slot. No dead binding can land in the map.
- Q5 Rebind target: the whole action inside one scheme, replaced by the captured input. The CR-5 binding handle stays internal.
- Q6 Read rule: `ReadBindings` merges per action and scheme named by the lines. Unnamed bindings stay.
- Q7 Phase 1 demo: rebind one key live in HelloPanel through a button.
- Q8 Conflict path: commit the new binding, report both action names through a slot, and keep both by default. The rebind writes the binding array directly, past the throwing bind-time check.
- Q9 Silence: during the listen, action values and command invokes go off. The device track and `OnSchemeChanged` keep running, and a suppressed frame emits no release edge.
- Q10 Format coverage: all nine `InputKind` shapes round-trip. `code`, `code1..code3`, `mods`, and `scale` appear when they are not at their default.
- Q11 Scheme argument: it names the tag of the new binding and the set of bindings that it replaces. It filters no input, so any fitting input is captured.
- A1 The listen branch sits inside the existing `ReadFrame` pass (`UiActionMap.Read.cs:259`) after its pair test. It allocates 0 bytes with the conflict check. `ActionMapAllocationTests` gains a body that drives a live rebind, plus a fixed-increment assert, and a plant fails it. `WriteBindings` and `ReadBindings` run at load time and may allocate.
- A2 The feature is Framework-only and free of project-file change: no `BrutalUi.Core` file, no `BrutalUi.Glfw` file, and no `.csproj` change. The raw state already carries keys, pointer buttons, the delta, the scroll, and the 16 gamepad slots.
- A3 This feature ships `UiScheme.Default` (deferred CR-8) as `public const int Default = 0`, and uses `SchemeName(id)` for the bytes that one line writes. `SchemeName(0)` is empty, so the writer emits an explicit token for a default binding.
- A4 Because Q8 keeps both, the commit path bypasses `FindClash`. A clash against a default (id 0) binding reports too, since `SchemeClashes` makes id 0 clash with any tag in either order.
- A5 Capture candidates follow the `InputKind` table: a key, a mouse button, a gamepad button, a stick, an axis, a pointer delta above a threshold, and a non-zero scroll. "Above the deadzone" means a stored value that is not exactly 0, because `GlfwUiInput` bakes the deadzone in at poll time.
- A6 `ResetBindings` restores a snapshot that the map copies once on the first `Activate`, before any rebind. `ReadBindings` does not change the snapshot.
- A7 The format is a version line, then one line per binding. The fields are `action`, `scheme`, `device`, `code`, `code1`..`code3`, `mods`, and `scale`. `WriteBindings(Span<byte>)` returns the byte count, and a short span returns the needed count with nothing written.
- A8 A bad line is skipped and counted, never thrown: an unknown action, an unknown field, a bad number, or an out-of-range code. The reader returns the applied and skipped counts. An unknown version applies nothing and reports the version as the failure.
- A9 Escape (GLFW code 256) cancels the listen by default through one settable property. The listen consumes it before the `Cancel` bind of the map can fire, so the reset path of HelloPanel stays reachable.
- A10 No public per-binding handle ships. The CR-5 hooks stay internal to the `UiActionMap` partials. The Framework test assembly has no `InternalsVisibleTo` today, so every test reaches this feature through its public API.

### Decision 1: The listen lives inside `ReadFrame`, and a listening frame returns early
**Choice:** `ReadFrame` keeps its pair test, then runs `if (_rebindOpen) { RebindScan(context); return; }`. The four passes of input-actions run only in a frame that is not a listen. `RebindScan` ends with the device store and `ReportSchemeChange()`.

**Rationale:** A1 places the branch there. The branch needs one test and one call. The early return makes Q9 exact. The value loop reads a copy of the binding array, taken at the top of `ReadFrame` (`UiActionMap.Read.cs:270-273`). A commit frame must not run that loop. That loop would drive the old binding with the press that landed the new one. The return also skips the finish pass, so no action emits a release edge for input that the listen took. It skips the gamepad invoke pass too, so no command runs. `ReportSchemeChange` still runs, so the device track and `OnSchemeChanged` keep working (Q9).

**Alternatives:** (a) A separate `UiContext.OnInputRead` handler that `BeginRebind` sets. A second slot write breaks the `IsActive` pair test and the one-map rule. Core would then need to know about a listen, against A2. (b) Run the whole read, then drop the values. A conflicting press then runs a command in the same frame, against Q9.

### Decision 2: The scan reads the raw view, and a digital capture needs a fresh press edge
**Choice:** `RebindScan` reads `context.Input`, and not `context.GameInput` (Q1). A key, a mouse button, and a gamepad button are candidates only through `WasPressed` or `pad.Pressed`. The held mask never makes a candidate. The analog shapes are candidates when their stored value is not exactly 0. The pointer delta is the exception: it needs a length above `RebindDeltaThreshold = 8f`.

**Rationale:** `GameInput` empties the key part when the context holds any focus. It empties the pointer part when the pointer is over the UI (section 9, item 11). A rebind menu is exactly the case where a widget holds focus or a pickable root covers the window. A gated scan could then never capture, and the demo in HelloPanel would die. The press-edge rule is what lets the settle frame work with no per-code down memory.

A click or a key that opened the listen has no edge in the settle frame. So a binding never lands from the input that started the rebind. A key held from before the listen stays out until the player presses it again. Framework references no Glfw, so the deadzone that the poll bakes in makes "not exactly 0" the right above-deadzone test for the pad (A5, A2). The pointer delta is unfiltered screen movement, so it needs its own threshold. A one-pixel jitter would otherwise capture a `MouseDelta` binding every time a player nudges the mouse.

**Alternatives:** (a) Scan `GameInput`: no rebind under a focused widget. (b) Use `IsDown` for the digital shapes. A slow mouse-button click that spans the settle frame then captures the left button. A key held from the menu press captures at once. (c) Snapshot the whole down bitset at `BeginRebind` and require a change. That is a 136-byte copy inside a frame path that a click can reach.

### Decision 3: The rebind replaces one action-and-scheme group and appends at the end
**Choice:** `RemoveBindings(_rebindAction, _rebindScheme)` compacts the array in place, and `Append` writes the new binding last. The order of every other binding stays.

**Rationale:** Q5 names the target as the whole action inside one scheme. Q11 names the scheme argument as the set that the rebind replaces. A `Move` action can hold a `KeyVector` in one scheme and a stick in another. Only the named group goes. A composite action cannot be rebuilt part by part (Out of scope), so the group ends with exactly one binding.

Removing before appending keeps the array length flat. That is what lets a commit allocate nothing after warm-up (A1), and it keeps the seventeenth gate at 0 bytes. A compaction, not a sentinel mark, is what keeps an in-flight frame read safe. An entry with `Action = -1` would throw an index error in any loop that already copied the array.

**Alternatives:** (a) Overwrite the first binding of the group and leave the rest. A rebind of `Move` would then leave a stale `KeyVector` that still drives the action. That is a dead binding of the kind Q4 forbids. (b) Swap-with-last removal: cheaper, but it reorders every binding. It would change the press-path resolve order across the whole list, not only for the rebound action.

### Decision 4: The commit bypasses the throwing duplicate check, reports, and keeps both
**Choice:** `CommitRebind` never calls `FindClash`. It calls `FindConflictAction` before the removal, then commits, then reports the two action names through `OnRebindConflict`. Both bindings stay.

**Rationale:** Q8 names exactly this order, and A4 states that the commit path must bypass `FindClash` (`UiActionMap.Bindings.cs:1137`), because the bind-time rule throws. The shipped throws are right for a build and wrong for a player. A rebind must tell the player about the clash and let the game decide, and not fail the click.

The scan reads the action index of the clashing binding before the removal. That is the fix for review CR-5, which says the shipped finds throw the action of the binding away. `SchemeClashes` is reused, so a default (id 0) binding clashes in either direction (A4).

**Alternatives:** (a) Clear the binding of the other action. That silently takes a key away from an action that the player never chose to edit. (b) Throw on a clash: it breaks the click and repeats the build-time rule in a runtime path. (c) Refuse the commit and report. Then a player who wants both, and will fix it later, has no way. Q8 names the commit-first order.

### Decision 5: The defaults snapshot comes from the first `Activate`
**Choice:** `Activate` calls `CaptureDefaults()`, guarded by `_defaultsCaptured`, and the copy allocates one `InputBinding[]`. `ResetBindings` copies it back into the existing array and restores the count.

**Rationale:** A6 names the first `Activate` as the capture point. `Activate` (`UiActionMap.cs:504`) is the only hook that a map reaches between a build and a frame. The framework has no "build finished" call. The binds of a game spread over several constructors, and `UiManager` activates the map in the mode diff. The copy is once, so a mode switch keeps the same snapshot. The snapshot stays the build bindings that the first play of the mode saw.

**Alternatives:** (a) Copy at the first `BeginRebind`. Then a game that rebinds before its first activation has no snapshot. A reset could not restore binds added between an activation and the first rebind. (b) A new public `FinishBuild()` method: one more member of the build surface. Every existing game and every shipped test would have to call it. (c) Re-derive the defaults from the bind calls. That means a second copy of all nine bind bodies, or a recorded call log.

### Decision 6: `WriteBindings` returns a needed count, and the two passes share one writer
**Choice:** `WriteBindings(Span<byte>)` returns the bytes written. When the span is too short it returns the needed count with nothing written. A private `WriteLine(in BindingText, Span<byte>, ref int, bool measure)` serves both passes.

**Rationale:** A7 names the shape. It has no precedent in `src/`. `TextField.GetText(Span<byte>)` returns the bytes written and never a needed count. The HelloPanel formatters throw `InvalidOperationException` when their scratch is too small.

The shape is right here, because the game owns the file and cannot know the byte count of a list that it did not build. One binding line is as long as its action name, its scheme name, and its code digits. One shared writer makes the two counts agree exactly, which a test pins. The alternative, a throw, is wrong for a load-time call that a game wraps in its own file write. A growable return, such as a `byte[]`, would put an allocation in the public signature.

**Alternatives:** (a) A `byte[]` return: an allocation that the caller cannot avoid. A game with its own buffer pays for a copy. (b) The `TextField` shape: a short buffer truncates one line in silence. That is exactly the silent data loss that this feature must not have.

### Decision 7: `device` carries the numeric `InputKind`, with the values pinned
**Choice:** The `device` field of a line holds the `InputKind` number 0 to 8, and `InputKind` gains explicit values so the numbers cannot move. Section 9 publishes the table. `InputBinding` gains no `device` field.

**Rationale:** Q10 asks that all nine shapes round-trip, and `InputBinding` holds no device. The device comes from the kind (control-schemes Decision 4). A line that stored only "keyboard" or "gamepad" could not tell a `KeyVector` from a `Key`, so the nine shapes would not round-trip.

A7 and Q10 together settle the field set, and Notes records the gap against requirements line 16. Numbers match Q2, which puts codes and modifiers as numbers and ships no name table. Explicit enum values cost nothing, and they make the private enum order a stored contract instead of an accident. Without them, one inserted member would silently rewrite every saved file.

**Alternatives:** (a) Infer the kind from the field shape and the action type: ambiguous between `Key`, `MouseButton`, and `GamepadButton`, which all hold one code. (b) A public `InputKind`: against A10 and the "no new public type" surface, plus a Core-style enum that a game would then store.

### Decision 8: Two nested delegates, three public status constants, and a `ValueTuple` return
**Choice:** `RebindResultHandler` and `RebindConflictHandler` are nested public delegate types inside `UiActionMap`, next to the nested `CreateInfo`. The status of a result is one of three public `const int` members on the map. `ReadBindings` returns `(int Applied, int Skipped, int Version)`.

**Rationale:** Q4 and Q8 name two slots. A slot that carries two action names needs a delegate whose parameter list carries `ReadOnlySpan<byte>`. The repo pattern for a slot is a named delegate (`UiInputReadHandler`, `UiUnhandledInputHandler`, `UiSchemeChangedHandler`). `UiActionMap.CreateInfo` already shows that a nested public type belongs to the class that owns it, so the surface grows only on `UiActionMap` and `UiScheme.Default`. That is exactly the confirmed list.

Three status codes do not need an enum. Two public enums would appear in the docs for three values that a slot names, and `UiScheme.Default` already shows the const-int shape that A3 ships. The tuple gives the three numbers that A8 names, with no new type. `ValueTuple` is a struct, so the read allocates nothing on its own.

**Alternatives:** (a) Two new top-level files in the `Actions` folder: the shape that `UiSchemeChangedHandler.cs` uses. It would add two top-level public types to an epic that asked for none. (b) `Action<...>`: `ReadOnlySpan<byte>` cannot be a generic type argument, and an anonymous delegate in a public API goes against every shipped slot. (c) A public `RebindStatus` enum: one more type for three values, and a game that reads a status never names the type.

### Decision 9: Silence at five path entries, and a `PushGamepad` that stores then returns
**Choice:** `_rebindOpen` is the first test in `PressKey`, `PressMouseButton`, and `InvokeAction`. `PushGamepad` writes `_gamepad` and returns 0. `HandleInput` keeps its repeat rule and its text guard, and the two press methods that it calls now give `false`. The frame read runs no value pass. The five queries keep their bodies and read the frozen values.

**Rationale:** Requirements line 13 says the map gives no value and invokes no command. The five paths are the only ways a command runs (`UiActionMap.Read.cs:34`, `:73`, `:100`, `:133`, `:154`). Guarding each entry, instead of guarding the shared `Invoke`, keeps the rule visible at each path. A new caller cannot bypass it.

`PushGamepad` stores before it returns, and that is what makes an edge lost rather than queued, in the habit of control-schemes CR-7. If it stored nothing, a button held across the listen would produce a press edge after the listen closed. The game would then run a command for a press that the player made during the rebind. The queries need no guard, because the map wrote nothing in a suppressed frame. Each value and each flag keeps its last read state, and the switch rule of input-actions stays intact.

**Alternatives:** (a) Guard only `Invoke(int action)`: the value loop of `ReadFrame` still fills each action and each Button flag, against Q9. (b) Zero every value while listening: each suppressed frame would run the finish pass and emit a release edge, which Q9 forbids.

### Decision 10: The reject reports once per frame, and the cancel key test comes before the fit test
**Choice:** A candidate that does not fit the action type leaves the listen open and reports `RebindRejected` with its code. The map reports in every frame that a rejected candidate stays live. The scan reads the cancel-key press before the fit test.

**Rationale:** Q4 names all three parts: reject, stay in the listen, and report the reason. A held analog value is live in each frame, so a per-frame report is the honest reading of "report the reason". A game that shows the reason on screen needs no extra work of its own.

A quiet repeat costs one delegate call in a frame where the map already does nothing. The cancel-first order is what lets a game rebind a Vector2 action and still press Escape to get out. Escape is a mismatch for a Vector2, so a fit-first order would report a reject and leave the player in the listen.

**Alternatives:** (a) Report the reject only once per distinct code: it needs a remembered code per listen, and that is one more field for a UI nicety. (b) Close the listen on a reject: against Q4, and a player who mistypes would have to reopen the menu.

### Decision 11: Two new partial files, and no change to `UiActionMap.Bindings.cs`
**Choice:** `UiActionMap.Remap.cs` holds the listen, the capture, the commit, the conflict report, `ResetBindings`, and the snapshot. `UiActionMap.BindingsText.cs` holds the text pair, the line codec, and the internal handle. `UiActionMap.Bindings.cs` keeps every line of the 18 `Bind*` members, `Find`, `FindAllowed`, `FindClash`, `FindValue`, and `Append`, exactly as control-schemes shipped them. `RemoveBindings` lives in `Remap.cs`, beside the commit that calls it.

**Rationale:** The chosen approach follows the pattern that `.Bindings.cs`, `.Read.cs`, and `.Schemes.cs` set: one partial file per concern, with the private helpers beside the members that call them.

Leaving `Bindings.cs` byte-identical is the cheapest possible proof that the shipped 18-bind surface did not change, and it is a checkable criterion in the Definition of Done. The duplicate rule of the bind surface and the conflict rule of a rebind are two different rules, so they do not share a method body.

**Alternatives:** (a) Put the codec in `Bindings.cs`: it holds 1286 lines today, and a text format is not a bind. (b) Move the removal into `Bindings.cs` beside `Append`: then the shipped bind file changes, and the quality check gets weaker for no gain.

## Notes

### Requirement-versus-code conflicts, kept as the interview settled them

- **N1: the line fields against `InputBinding`.** `requirements.md:16` names five line fields: the action, the scheme, the device, the code, and the modifiers. `InputBinding` (`UiActionMap.cs:695-739`) holds a kind, four codes, a scale, a scheme, and an action index. It holds no `device` field. Q10 and A7 settle the field set: `action`, `scheme`, `device`, `code`, `code1`..`code3`, `mods`, and `scale`. The `device` field carries the numeric `InputKind` id, because the device of a binding comes from its kind (control-schemes Decision 4) and the nine shapes must round-trip. `InputKind` gains explicit values, so the numbers are a stored contract. See Decision 7.
- **N2: "the next input of that scheme".** `requirements.md:12` says the next input of that scheme becomes the new binding. The map has no tag-to-device rule, and `SchemeAllows` (`UiActionMap.Schemes.cs:287`) filters nothing while the map holds no lock. Q11 settles it: the scheme argument names the tag of the new binding and the set of bindings that the commit replaces. It filters no input, so any fitting input is captured. Note the consequence: a lock does not narrow the capture either, because the scan reads the raw view (Q1). Even a locked map captures any fitting input, and the tag then decides which bindings the commit replaces. The fit test of the action type is the only filter. See Decision 2 and Decision 3.
- **N3: the needed-count return.** `requirements.md:16` asks for a needed count that no code in `src/` returns today. `TextField.GetText(Span<byte>)` returns the bytes written and never a needed count. The HelloPanel scratch formatters (`SchemeText`, `StickText`, `MoveText`) throw `InvalidOperationException` when the scratch is too small. A7 keeps the needed-count shape, and Decision 6 records it as a new shape for this repo, with its reason.
- **N4: the silence across five paths, and the per-scheme one-input rule.** `requirements.md:13` says the map gives no value and invokes no command. The paths are five separate ones: `HandleInput` (`UiActionMap.Read.cs:154`), `PressKey` (`:100`), `PressMouseButton` (`:133`), `PushGamepad` (`:34`), and `InvokeAction` (`:73`), plus the value loop of `ReadFrame`. Decision 9 guards each entry. Item 14 states the per-scheme one-input rule, and Q8 keeps both, so a conflicting rebind bends it. One input can then hold two actions in one scheme. The press path resolves the first binding in the order of the bind, and the frame read sums both. Task 5.4 corrects the **The build rules.** sentence so the rule and the exception sit together.
- **N5: the build-time copy with no capture point.** `requirements.md:15` asks for a copy of the defaults from the build, and no code marks the end of a build. `AddAction` and the 18 binds set no flag, and no "build finished" hook exists. A6 settles it as the first `Activate`. Two consequences follow, and tests pin both. A game that binds after its first activation loses those binds on a restore. A map that was never activated holds no snapshot, so `ResetBindings` gives `false`. See Decision 5.
- **N6: Escape as the cancel key, which HelloPanel already binds.** `requirements.md:12` names Escape as the default cancel key, and `samples/HelloPanel/HelloState.cs:106` already binds Escape (GLFW 256) to `hello.reset`. A9 settles it: the listen consumes Escape, and `PressKey` gives `false` during a listen. The reset path of HelloPanel therefore stays reachable in every frame that is not a listen. Two sample rules follow. The phase 1 demo rebinds `NavigateUp`, never `Cancel`. The sample must not rebind `Cancel` onto a code that the game later uses as its cancel key. F3 and the manual step 9 check both halves.
- **N7: CR-5 internal hooks, reachable only inside the class.** No `InternalsVisibleTo` exists for `BrutalUi.Framework.Tests`, so the internal hooks of input-actions review CR-5 (`docs/features/input/input-actions/code-review.md:135-145`) are visible only to the `UiActionMap` partials. A10 settles it, and the feature honors it: `BindingText` and `TryReadBinding` are internal and serve the writer and the commit, and every test reaches the feature through the public API. No test can read one binding, so `BindingsRoundTripTests` proves the nine shapes by driving frames and reading the five queries. It compares no fields.
- **N8: the reader sentence against the merge rule.** `requirements.md:17` says `ReadBindings` "replaces the bindings of each named action" and skips a bad action or line. Q6 and A8 add the scheme to the key and the counts to the return. The unit of replacement is one action in one scheme. An unnamed pair keeps its bindings, a bad line is skipped and counted, and an unknown version applies nothing. The plan implements Q6 and A8, and item 16 states the merge rule.

### Open items this plan decided, and one it did not

- The value of the pointer-delta capture threshold (`RebindDeltaThreshold = 8f`) is a choice of this plan. A5 names a threshold without a size, and a raw pointer delta is unfiltered screen movement. It is one private constant, and `APointerDeltaAboveTheThresholdCommitsADeltaBinding` pins both sides of it. A person who wants a different number changes one line and one test.
- The reject slot reports once per frame while a rejected analog candidate stays live (Decision 10). A game that wants one report per distinct code can hold its own last code. This plan adds no dedup state.
- No open scope question blocks phase 1: Q7 names its demo, so slice rules 11 and 12 are satisfied by the confirmed demo.

### Migration risks, stated in one place

- The 18 `Bind*` surface, the five queries, and the scheme API change no line. `UiActionMap.Bindings.cs` keeps an empty diff, and twelve existing Framework classes pass with no edit.
- `InputKind` gains explicit values that equal its current declaration order, so no behavior changes today. The risk is a later reorder of a stored contract, and section 9 plus the enum remarks say so.
- A rebind commit puts the new binding at the end of the array, so a clashing input resolves to a different action than before the rebind. Only a rebind moves an order. Nothing that skips `BeginRebind` sees a change.
- The defaults snapshot comes from the first `Activate`, which `UiManager` does in the mode diff. A game that binds after the first apply of its mode loses those binds on a restore. HelloPanel is safe, because its map builds in the `HelloState` constructor.
- `ReadBindings` replaces a named action-and-scheme group. A game that reads a file made by an older version of the map, or made by hand, loses a binding only when the file names the same pair. A version mismatch applies nothing.
- HelloPanel gains one label and two buttons, so the draw-command and vertex counts of the smoke run move, as they did for labels five and six. `context.md` tracks the re-measure as a display-host check.
