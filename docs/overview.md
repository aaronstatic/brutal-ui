# brutal-ui - Overview

**Last Updated:** 2026-11-17
**Version:** v2.8

## Project Summary

brutal-ui gives BRUTAL developers a retained-mode game UI framework with zero allocations in the frame loop. It ships as NuGet packages and renders through the Dear ImGui draw list that BRUTAL already provides. It brings the panel, mode, store, and window model of mosaic-ui to BRUTAL with no Unity dependency.

## Public-alpha feedback

The repository went public on 2026-11-09. The first outside reports named three gaps: UI scaling, in-game drag and drop, and shadows. Phase 6 of `docs/technical-design.md` now holds them. The content-scale event reaches the `UiContext.OnContentScale` slot. No layer consumes it yet. Window dragging ships with the phase 4 window model. Item drag needs a drag source, a ghost, and drop targets. The mission statement defers effects beyond the draw list. Shadows lead that work. One game also targets SDL3. `BrutalUi.Core` knows nothing about the windowing layer, and the input seam is public. A `BrutalUi.Sdl` adapter over `Brutal.Sdl` is a port, not a redesign. It is a candidate, not yet planned.

## Integration Points

- **dev-ops → every later epic:** Each later epic adds code to the projects of `dev-ops/solution-skeleton`. Each later epic runs `scripts/test-linux.sh` and `scripts/test-windows.ps1`.
- **GPU smoke contract:** A sample accepts `--frames N` and exits with a code. Both test scripts use this contract.
- **System dependency:** `Brutal.Vulkan` loads the unversioned `libvulkan.so` on Linux, so the machine needs `libvulkan-dev`. On Windows it loads `vulkan-1.dll` from `System32`.
- **core-tree → later epics:** The imgui-renderer epic adds `UiContext.Draw` and plugs text into the measure callback slot of `LayoutNode`. The style-system epic writes `ComputedStyle` from the cascade. The input epic adds events and hit testing on `Element`.
- **Allocation gate:** `ThousandElementAllocationTests` fails the test scripts when `UiContext.Update` or `UiContext.Draw` allocates on a warm 1000-element tree. Each zero-byte gate calls `AllocationGate.ReleaseAllocationContext()` before its measure.
- **imgui-renderer → later epics:** `IUiRenderer` is the only path to pixels. The style-system epic writes the paint members of `ComputedStyle`. The input epic reads the layout rects and `LayoutNode.ContentInsets`. The world-space epic adds a private draw list behind the same interface.
- **GPU smoke contract (Phase 1):** The HelloPanel smoke run prints 3 lines and exits with code 1 when `Update` and `Draw` allocate after warm-up.
- **style-system → later epics:** Code sets an inline value through `Element.Inline`, and `Element.Style` is `ref readonly`. The input-routing epic sets `Element.States`, and the pseudo-state rules restyle the subtree. The markup epic loads a sheet through `StyleSheetParser` in `BrutalUi.Markup`. `UiContext.Update` runs the style pass, then the transition pass, then layout.
- **input-routing → later epics:** A handler registers on the capture and bubble slots of `Element` at build time. `UiContext.Update` drains the event ring, then runs the style pass, the transition pass, and layout. The interactive-elements epic builds `Button`, `Toggle`, `ScrollView`, and `TextField` on these events and on the focus owner. The game reads `UiContext.RoutingGate` after `Update`.
- **interactive-elements → later epics:** A widget reports each change through an `Action<T>` delegate slot that the game sets at build time. The framework epic binds a widget to a command or a store through these slots. The markup epic registers each widget type by name. `UiContext.Update` now runs a caret pass for a focused `TextField` after layout. `ThousandWidgetAllocationTests` puts each widget into the 0-byte gate.
- **GPU smoke contract (Phase 2):** The HelloPanel smoke run drives each widget in each frame, prints a fifth line with six counts, and exits with code 1 when a count is 0.
- **state-and-commands → later epics:** A binding is a Core `ElementBinding` struct on `Element`. `UiContext.Update` runs the binding pass before the style pass. A button and a key reach the same `CommandRegistry` by a UTF-8 name. The panels-and-modes epic binds a panel root to a store and lists the active action maps of a mode. The xml-markup epic calls `BindCommand` for the `command="..."` attribute. `UiContext.OnUnhandledInput` holds one active map.
- **GPU smoke contract (Phase 3):** The HelloPanel smoke run prints a sixth line with the store counts, and exits with code 1 when a count is 0.
- **GPU smoke contract (Phase 3, modes):** The HelloPanel smoke run switches the mode in each frame after warm-up, prints a seventh line with the mode counts, and exits with code 1 when a count is 0.
- **panels-and-modes → xml-markup and later:** `UiManager.Register` takes the panel, layout, and mode records that the xml-markup loader reads from XML. `UiContext.OnBeforeUpdate` is the one Core slot of the framework mode diff. The diff runs first in `Update`, before the input pass, so a key in the frame of a change reaches the action map of the new mode. panel-sample adds the two HelloPanel modes, the seventh smoke line, and the `ModeDiffAllocationTests` gate.
- **input-state (input epic) → later features:** The drain of `UiContext.Update` writes `UiInputState` entry by entry through three hooks in `DrainEvents`, and writes the gated view `ui.GameInput` at the end of the drain. gamepad-axes calls `UiContext.SetGamepad` from `GlfwUiInput.PollGamepads`; input-actions reads `GameInput` in `UiActionMap.Update`; control-schemes and binding-remap build on the typed actions. `ClearHeldKeys` releases each held key at the end of the next drain, and `GlfwUiInput` calls it on a focus loss and on a `KeyboardEnabled` switch to `false`. The state measures 804 bytes and writes and reads 0 bytes after warm-up.
- **binding-remap (input epic) closes the stack:** The remap edits the binding list of `UiActionMap` in place, inside one scheme. The game owns the file: Framework ships no file IO. `WriteBindings` and `ReadBindings` carry the list as UTF-8 lines with a version header. The nine `device` numbers are the explicit `InputKind` values, so a saved file is a stored contract. No later member may reorder it. A mode switch ends a listen, because `Activate` closes it. spacegame map-controls keeps compiling unchanged: the 18 `Bind*` signatures, the five queries, and the scheme API change no line.
- **builder-api (markup epic) sets the surface for the epic:** Each of the 12 value methods names one future XML attribute, so xml-element-loader writes one table row per value method and reads the same property rules. `Capacity` and `ScrollSpeed` exist only in the create info (A6), so they have no method, no public setter, and no row. A row for `value` must run after the rows for the range, because `Value` clamps to the current range. `ElementBuilder`, `Command`, and `Find` are the three hooks the later features call: the loader maps attributes onto the builder, binding-attributes registers `command` and `bind-text` on the loader hook and uses `Find` in panel code, and `tests/BrutalUi.Core.Tests/Shared/TreeCompare.cs` is the compare that proves "markup equals code" for each template. `TreeCompare` compares delegate invocation counts and not identity, so a bound tree and a builder tree test equal, and it does not compare `Inline`, `Layout`, `Style`, `Dirty`, or `BindingCount`; a template that sets one of those extends the helper in the loader feature.
- **element-generator (markup epic) opens the type seam for every later element:** A game or a Phase 4 epic (`ListView`, `DataList`, `WindowChrome`) adds a table entry with one `[TemplateElement("Name")]` on the class, or on a static declaration class with `Target = typeof(Name)` for a type of another assembly, plus `[TemplateFactory]` and `[TemplateCreateRow]` when create rows are needed. The generated `Register<Id>Elements(this TemplateLoader)` takes the whole assembly; the manual `Register` stays public. A consumer project that references Markup as a project adds the generator `ProjectReference` analyzer line (the analyzer does not flow through a project reference); a package consumer needs no line, because the generator rides in `analyzers/dotnet/cs`. A bad marked type stops the build with one `BRUTALUI000N` error at the code at fault. `AttributeContext` carries the public reads (now nine), so a custom setter never touches internals. The hook contract (`AddAttributeHandler`, `AttributeHandler`, `AttributeContext.AddError`, `TemplateError`) is unchanged, so binding-attributes builds on it in parallel.
